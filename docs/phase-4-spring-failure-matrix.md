# Spring Phase 4A — PostgreSQL simulated runtime failure matrix

Risk: `HIGH_RISK`. Every Spring process that constructs a PostgreSQL `DataSource` (including `bootRun`) is an explicit
maintenance writer. It fails *before DataSource/Flyway construction* unless both `RUN_POSTGRES_INTEGRATION_TESTS=true`
and `SPRING_EXCLUSIVE_MAINTENANCE=true` are present, and it rejects a local `127.0.0.1:8080` listener to prevent a
concurrent TypeScript writer. Default Gradle unit tests do not create a PostgreSQL connection.

## Maintenance test command

```powershell
# Stop the TypeScript API first. The pre-DataSource guard rejects a local 8080 listener.
$env:RUN_POSTGRES_INTEGRATION_TESTS = 'true'
$env:SPRING_EXCLUSIVE_MAINTENANCE = 'true'
./gradlew.bat test --tests '*Postgres*IntegrationTest'
```

No test may truncate a table or issue a broad `DELETE`. `PostgresFixtureCleaner` tracks every supported AgentStore FK
record type and deletes only registered UUIDs in reverse dependency order.
